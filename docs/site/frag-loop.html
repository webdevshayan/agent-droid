The agent loop

AgentDroid is designed around one loop that any shell-capable agent can run — Z.ai agent mode, Claude Code, Cursor, Codex CLI, Aider, or your own harness. Prefix every command with --runtime fake to run it against the simulated app with no device attached:

StepCommandWhat the agent does
1 · Discoveragentdroid devicesConfirm a device is attached; pick one with --serial if needed.
2 · Readagentdroid snapshotEvery line is one element and one decision candidate. Use --xml for the full tree.
3 · Actagentdroid tap @e3One action per command. Branch on the exit code: 0 acted, 1 environment problem, 2 malformed command.
4 · Verifyagentdroid snapshotConfirm the screen changed as intended before acting again.

Ref semantics — read before scripting

Refs are positional and stateless: every ref command re-dumps the current screen and picks the Nth element. Each command is self-consistent, but a stale ref can point elsewhere after a screen change — so snapshot immediately before acting, and snapshot again after every action.

A minimal agent prompt

You are testing an Android device with the agentdroid CLI.
Rules:
- Run `agentdroid snapshot` first and after EVERY action; refs are always
  re-resolved against the current screen.
- Act only by ref (`agentdroid tap @e3`) or by coordinates for swipes.
- `agentdroid type "text"` goes to the focused element: tap the field first.
- Exit code 0 = success, 1 = retryable environment error, 2 = your command was
  malformed — fix the command, do not retry it blindly.
- State what you did and what you verified after each step.

Piping tips

Output is plain text with a stable line format, so agents can grep it — agentdroid snapshot | grep -i 'sign in' — or diff two snapshots to detect screen transitions programmatically.
